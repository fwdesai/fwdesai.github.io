# fwdesai.github.io

Personal site — Astro 7 + Tailwind 4, deployed to GitHub Pages. Ships zero
JavaScript to the browser.

Live at **https://fwdesai.github.io**

---

## Running it locally

```bash
npm install      # first time only
npm run dev      # http://localhost:4321
```

Edits show up instantly — no need to restart.

**Before you push, always run the production preview:**

```bash
npm run build && npm run preview
```

This serves the real built site (also on port 4321). The dev server is more
forgiving than GitHub Pages about paths, so this is the step that catches a
broken link before a visitor does.

To check the layout on your phone, run `npm run dev -- --host` and open the
`Network:` URL it prints, from a device on the same wifi.

## Adding a project

Everything lives in **`src/data/projects.js`**. Copy an existing entry, change
the fields, and both the `/projects` grid and the `/projects/<slug>` detail
page appear automatically. You do not create a new page file.

### Where the photos go

```
public/images/projects/<slug>/
```

The folder is already created for each project. Drop image files in, then
reference them in `projects.js` with a **leading slash**:

```js
cover: '/images/projects/mri-quadrature-digitizer/board-top.jpg',

images: [
  {
    src: '/images/projects/mri-quadrature-digitizer/board-top.jpg',
    alt: 'Top side of the assembled digitizer board',
    caption: 'Assembled board, top side.',
  },
],
```

- `cover` — the single photo on the grid card. Roughly 4:3 crops look best.
- `images` — the gallery on the detail page. The first one spans full width.
- Leave either empty and you get a labelled placeholder instead of a broken
  image, so nothing looks broken while you're still gathering photos.

**Resize before committing.** Photos straight off a phone are 3–8 MB. Aim for
about 2000 px on the long edge and under 500 KB:

```bash
sips -Z 2000 photo.jpg --out public/images/projects/<slug>/board-top.jpg
```

## Updating the resume

1. Drop the new PDF in `public/`.
2. Update `resumePdf` and `resumeUpdated` in `src/data/site.js`.
3. Regenerate the preview image:

```bash
./scripts/render-resume.sh public/Your_New_Resume.pdf
```

That script needs `brew install poppler webp` once.

The resume page shows a rendered **image** plus "Open PDF" and "Download"
buttons, rather than an embedded `<iframe>`. That's deliberate: iOS Safari
renders an embedded PDF as a frozen, unscrollable first page, and Chrome on
Android often shows nothing at all inside a frame. A plain top-level link to
the PDF works correctly on both.

## Adding a new page

Create a file in `src/pages/`. The filename becomes the URL:
`src/pages/notes.astro` → `/notes`.

```astro
---
import Base from '../layouts/Base.astro';
---

<Base title="Notes">
  <h1 class="text-4xl leading-tight">Notes</h1>
  <p class="mt-4 text-lg">...</p>
</Base>
```

To add it to the nav, append an entry to `NAV` in `src/data/site.js`.

## Deploying

Push to `main`. That's it — `.github/workflows/deploy.yml` builds the site and
publishes it. Takes about a minute; watch it under the repo's **Actions** tab.

One-time setup in the repo: **Settings → Pages → Source → GitHub Actions**.

## Layout

```
├── .github/workflows/deploy.yml   Build + publish on push to main
├── public/                        Served as-is at the site root
│   ├── Desai_Resume_8_16.pdf
│   ├── resume-preview.webp        Generated by scripts/render-resume.sh
│   └── images/projects/<slug>/    ← PROJECT PHOTOS GO HERE
├── scripts/render-resume.sh
└── src/
    ├── data/
    │   ├── site.js                Name, email, nav, resume filenames
    │   └── projects.js            ← ALL PROJECT CONTENT
    ├── layouts/Base.astro         Header, footer, <head> metadata
    ├── components/
    │   ├── ProjectCard.astro      Grid card
    │   ├── Gallery.astro          Detail-page photo gallery
    │   ├── Prose.astro            Renders the `sections` write-up
    │   └── ImagePlaceholder.astro
    ├── pages/
    │   ├── index.astro            /
    │   ├── resume.astro           /resume
    │   ├── 404.astro
    │   └── projects/
    │       ├── index.astro        /projects
    │       └── [slug].astro       /projects/<slug>  (one per data entry)
    └── styles/global.css          Colors, fonts, prose styles
```

Colors and fonts are the `@theme` block at the top of `src/styles/global.css`.
Change a value there and it updates across the whole site.

## Notes

- Requires Node 22.12+ (this repo is on Node 24 LTS). Astro does not support
  odd-numbered Node releases.
- This is a **user site**, so it serves from the root and `base` stays `/`.
  If it ever moves to a project repo, set `base: '/reponame/'` in
  `astro.config.mjs` and re-check every absolute path.
